8.5.2. Strengthening Cybersecurity in AI-Enabled Systems
AI systems are woven into daily life and critical infrastructure, which makes their vulnerability to attack a different order of problem than an ordinary software bug: exploiting one doesn't just crash a program, it can misdirect a decision the system was trusted to get right.

Adversarial attacks are one specific version of this: a bad actor exploits a weakness in how a model represents its input — a vulnerability first documented in image classifiers over a decade ago [[cite:C0364]] — to make the system produce a wrong answer with high confidence. A well-documented case is the "stop sign" attack: researchers showed that a small set of black-and-white stickers, placed on a real stop sign, caused a standard road-sign classifier to read it as a speed limit sign in the large majority of video frames captured from a moving vehicle [[cite:C0414]].

Countering that kind of attack takes more than a single fix:

<<list>>
- Adversarial training exposes a model to adversarial examples during training rather than only ordinary data, which measurably increases its resistance to the same class of attack [[cite:C0365]].
- Architectures built for resistance, through techniques like defensive distillation or randomized smoothing, aim to make a model's predictions change less under small adversarial perturbations. Defensive distillation's protection turned out to be weaker than first claimed once stronger attacks were tested against it [[cite:C0415]]; randomized smoothing has held up better, offering a certified robustness guarantee within a bounded radius around each input [[cite:C0416]].
- AI-driven defense turns the same machine-learning methods toward protecting the system: Darktrace's Enterprise Immune System is one deployed example, learning an organization's normal network behavior and flagging deviations from it in real time [[cite:C0417]].
- Security audits — penetration tests and red-team exercises run against the system before deployment, not only after an incident — catch vulnerabilities an adversary would otherwise find first.
- Shared threat intelligence between developers, security researchers, and other stakeholders means a technique used against one AI system gets recognized the next time it is tried against a different one, instead of every organization discovering it independently.
- Governance frameworks — industry standards and regulatory requirements written specifically for AI system security, not adapted after the fact from general software security rules — set a floor that does not depend on any one developer's judgment.
<</list>>

None of these measures work in isolation. A model hardened by adversarial training that runs on infrastructure nobody is monitoring is still exposed, and a well-monitored system built on an architecture that folds under a basic perturbation attack is exposed a different way. Security here means the whole stack, not the strongest link in it.
